# 欧易 OKX 合约机器人（模拟版）

Python 3.11+，无第三方运行依赖，带中文控制台。支持 **本地模拟** 和 **OKX 模拟盘**；没有实盘开关。示例策略是已收盘 K 线的快慢均线交叉，可做多或做空。它是开发和验证起点，不是已证明有效的投资策略。

Windows 电脑请先看 [电脑使用指南](DESKTOP_GUIDE.md)。安装 WSL 和 Python 后，可在解压目录双击 `start-windows.bat` 启动本地模拟。

已启用 Windows 手动 HTTP 代理的用户，可双击 **`connect-okx-demo.bat`** 打开欧易模拟盘连接向导。它复用现有代理，密钥在本机隐藏输入，不写入配置或日志。只读检查通过后，直接回车结束；明确输入 `DEMO` 才启动模拟订单。

机器人已经运行时，双击 **`monitor-windows.bat`**，在文件选择框中选择该机器人目录的 `.runtime-demo/status.json`（可以是旧版本文件夹），再打开 **http://127.0.0.1:8766**。这个“量化实验室 · 欧易模拟盘”读取现有机器人实际上报的权益、仓位、入场次数和订单日志，记录近期权益变化，超过 90 秒未更新或报告异常停止会提示。无需再次输入密钥，不启动第二个机器人，不修改状态文件；关闭网页和监控服务都不会停止交易机器人。订单成交和止盈止损有效性仍以欧易模拟盘为准。

监控页面可打开同一新版目录中已生成的历史回测报告。旧 `start-windows.bat` 的 `8765` 页面仍是合成行情演示，与新的模拟盘监控分开。

## 立即试用：不需要账户或 API Key

在仓库目录运行：

```bash
cd /workspace/etsy
python -m okx_bot web
```

程序只监听本机 `127.0.0.1:8765`。在运行程序的机器上打开本地面板，点击「开始模拟」，可查看行情图、权益、仓位、成交和事件。「停止模拟」会结束这一轮并结算本地虚拟持仓。这不是云端公网预览地址。

也可以直接运行命令行模拟：

```bash
python -m okx_bot paper --bars 320
python -m unittest discover -s tests -v
```

内置价格是确定性的**合成演示数据**，不是 BTC 历史行情，也不是实时行情。每次运行重新从虚拟本金开始；演示收益不能用来判断策略是否值得实盘。面板只控制本地模拟，不能启动交易所订单。

## 固定策略的真实历史回测

Windows 已配置手动 HTTP 代理时，双击 **`backtest-windows.bat`**。它使用公开接口下载最近 30 天的成交价 K 线、标记价格 K 线和历史资金费率，不读取 API 密钥，不下单，不修改正在运行的模拟盘。各段虚拟本金为 5,000 USDT；下载完成后生成并打开 `.runtime-backtest/report.html`。

报告比较固定参数的全区间、前 70%、后 30%，以及后段双倍手续费和滑点。每段独立重置本金与仓位，之前的数据只作均线预热，不按后段结果自动调整参数。回放遵循模拟盘的持仓规则：已收盘新交叉产生信号、下一根开盘近似入场、持仓期间不反手、标记价止盈止损、计入资金费、期末不强制平仓。

```bash
python3 -m okx_bot.backtest --days 30 --capital 5000
# 复用已保存的数据，离线重复验证：
python3 -m okx_bot.backtest --dataset .runtime-backtest/dataset.json --capital 5000
```

历史下载支持 7–60 天、15m 周期，另取慢均线长度加 1 根预热数据。必须取得连续且对齐的成交价和标记价格；资金费需要覆盖锚点。缺失时会停止，不插值、不用合成数据代替。数据快照与摘要、完整指标及交易序列保存在 `.runtime-backtest/dataset.json` 与 `report.json`，便于复查。摘要用于检查意外损坏，不是交易所来源签名。

历史 OHLC 无法复现盘口与逐笔时序。报告明确列出标记价与成交价的近似、回撤采样、当前合约规格假设，以及资金费覆盖检查的限制；未完整模拟强平、部分成交与网络延迟。后段交易较少或成本增加后表现变化时，不能据此认定策略稳定有效。真实历史接口仍需在能访问欧易的本机执行；离线测试结果不作为历史业绩。

## 默认参数

编辑 [config.paper.toml](config.paper.toml)；配置文件不含密钥。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 合约 / 周期 | BTC-USDT-SWAP / 15m | 只支持线性 USDT 永续；内置合成数据仅支持 BTC |
| 快 / 慢均线 | 5 / 20 | 真正发生交叉才发信号，不在启动时按已有方向开仓 |
| 本地虚拟本金 | 10,000 USDT | 模拟盘中也作为仓位计算本金上限 |
| 杠杆 | 1× | OKX 模拟盘固定逐仓、单向持仓 |
| 每笔目标风险 | 权益的 0.5% | 结合止损距离、假设手续费和滑点计算数量 |
| 名义仓位上限 | 权益的 10%，且不超过 200 USDT | 向下取整到交易粒度，金额不足时跳过 |
| 止损 / 止盈距离 | 1% / 2% | 从参考价格计算；实际成交和触发价可能不同 |
| 本次运行回撤阈值 | 5% | 相对本次权益高点；不是每日限额或最大亏损保证 |

这些值用于演示软件行为，没有根据你的资金或风险承受能力制定交易建议。

## 接入 OKX 模拟盘

1. 在 OKX **模拟交易**中创建独立 API Key，仅开读取与交易权限，不开提现权限；建议使用专用模拟账户，不混入手动订单或其他机器人。
2. 账户必须是单币种保证金模式（`acctLv=2`）、单向持仓模式（`net_mode`）。机器人不会替你切换账户模式。启动时所选合约必须无持仓、普通挂单和条件单；程序会设置并校验 1× 逐仓杠杆。
3. 可运行 `python -m okx_bot.connect --check-only`，在本机终端隐藏输入 API Key、Secret Key 和创建 API 时的 Passphrase；也支持复用安全环境变量 `OKX_API_KEY`、`OKX_API_SECRET`、`OKX_API_PASSPHRASE`。**不要把密钥发到聊天、写入源码或提交到 Git。** 本程序不自动读取 `.env`。
4. 网络需允许 HTTPS 访问 `www.okx.com`。保留代理和 TLS 校验。此版本固定此官方主机，不支持需要其他区域 API 主机的账户。
5. 先只读检查，再显式启动模拟盘：

```bash
python -m okx_bot market
python -m okx_bot demo-check
python -m okx_bot demo --ack-demo-orders
```

所有私有请求强制带 `x-simulated-trading: 1`，不能通过配置改成实盘。启动会预热历史 K 线，**不补下历史信号**，只在下一次新收盘 K 线发生交叉时考虑开仓。

OKX 密钥用于本地 HMAC 签名：仅能在网络代理中替换的占位密钥不能充当本地签名所需的真实 API Secret。程序不请求、不生成或猜测任何凭证。

## 订单与故障处理

- 下单前将唯一客户订单号和意图持久化；不会在网络超时后自动重发订单。订单已受理不代表已成交。
- 入场附带交易所原生止盈止损，使用标记价格触发市价单；程序核对成交数量、实际仓位及已激活的保护单。部分成交或保护单无法核实时，停止后续操作，要求人工检查。
- 模拟盘持仓只由交易所止盈止损退出；持仓期间忽略新的交叉信号，不反手、不加仓。本地模拟则支持在下一根 K 线开盘时按反向信号平仓并开反向仓位。
- **停止 OKX 模拟盘程序、数据中断、达到回撤阈值，不会自动平掉交易所持仓。** 已经核实的止盈止损留在交易所；故障状态下它们可能尚未激活。必须以 OKX 中的实际仓位和订单为准，必要时在 OKX 手动平仓、取消残留挂单。
- 未解决的意图、持仓或保护单会阻止重启。不要删除日志来绕过检查。在 OKX 确认已经空仓且没有残留普通/条件挂单后，运行 `python -m okx_bot demo-reconcile --ack-journal`。它只读核对交易所订单、仓位与挂单；仅在所有订单状态可确认且已终结时更新本地日志。订单仍未知、部分成交或查不到时继续阻止恢复，需要人工检查。
- 同一 API Key 在同一机器有进程锁；多台机器或不同 Key 无法用本机锁协调，不能同时操作同一模拟账户。

状态与审计文件默认位于 Git 忽略的目录：

| 文件 | 内容 |
| --- | --- |
| `.runtime/status.json` | 本地模拟最新状态，原子更新 |
| `.runtime/trades.jsonl` | 按运行 ID 追加的本地模拟平仓记录 |
| `.runtime/web-worker.log` | 控制台子进程输出 |
| `.runtime-demo/demo-journal.json` | 模拟盘意图、订单号与恢复检查记录 |
| `.runtime-demo/status.json` | 模拟盘最新轮询/停止状态 |

本地模拟每轮重置，不会从中断点恢复虚拟持仓。模拟盘每次启动也不会自动接管已有仓位。

## 验证范围与限制

- 测试覆盖信号去重、下一根 K 线成交、合约张数/币数换算、仓位上限、费用记账、跳空止损、回撤停止、API 签名、模拟盘请求头、未知订单结果及控制台访问校验。
- 新增历史快照、回测账务、时序分段、只读监控与 Windows 启动器检查。虚拟时钟覆盖一天的 5,761 次轮询，验证无历史重复开仓及持续状态更新；这不是实际连续 24 小时网络稳定性验收。
- 本地模拟对同根 K 线内同时触达止盈和止损的情况，按止损先触发处理；跳空止损按较差开盘价加滑点成交。回撤检查发生在每根 K 线开盘和收盘，不能发现盘中短暂触线后恢复的情况。
- 本地模拟包含固定手续费和滑点假设；**不模拟资金费、强平、深度、部分成交或网络延迟**。止损、预算和名义仓位上限都不能保证实际损失不超标。
- OKX 模拟盘 API 已根据官方 SDK 对照，并使用假交易所响应测试；尚未用用户账户完成真实模拟盘端到端验收。交易所返回的保护单结构不符合严格检查时会停止，不会假定保护已生效。
- 当前云环境的 OKX 域名访问被网络策略拒绝，也未配置模拟盘凭证。用户 Windows/WSL 电脑已通过代理取得公开行情、通过模拟账户只读检查并进入运行流程；完整入场成交和保护单链路仍待首笔模拟订单验收。
- 运行文件系统锁依赖 Linux/macOS 的 `fcntl`；Windows 可使用 WSL。该本机控制台不适合直接暴露到公网。

官方参考：[OKX API v5](https://www.okx.com/docs-v5/en/)、[OKX 官方 Python SDK](https://github.com/okxapi/python-okx)。
